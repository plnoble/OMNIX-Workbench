# 插件系统方案

> 状态：**已设计，建议缓做**。2026-08-20 定稿。
> 结论先写在这里：**技术上 OMNIX 已经具备条件，但现在不该做**——理由见第五节。

## 一、参考：deepseek-harness-desktop

[anywhere-labs/deepseek-harness-desktop](https://github.com/anywhere-labs/deepseek-harness-desktop)
（MIT，TypeScript，15.2k star，活跃）。核心理念：**「万物皆插件，桌面本身也是插件」**。
配套市场 [dsh.deepseek404.com](https://dsh.deepseek404.com/) 收录约 4,800–7,300 个插件。

它做对的三件事：

**① 传输层就是隔离层**

> Desktop 没有引入单独的 renderer IPC 插件系统，**也不把 Electron API 暴露给页面**。
> 第三方交互一律走回环 HTTP + WebSocket。

插件拿不到原生能力，只能通过宿主中介。这不是加了一层沙箱，而是**根本不给那条路**。

**② generation 生命周期**

切换 profile 就整代弃用重来，插件**不许跨代缓存**服务引用、窗口对象、子进程句柄。
——这正好对应本项目反复在修的「状态撒谎」那一类问题（会话在库里是 running、
进程早没了），只是它把纪律写进了架构。

**③ 极小的公开面**

只有两个公开服务契约（profile-service、pnpm），其余全私有。宿主自己的 UI 也是
「插槽贡献」，和第三方受同一套组合规则约束。

## 二、OMNIX 已有的对应物

**传输层不用新造**：

| DSH 的做法 | OMNIX 已有 |
|---|---|
| 回环 HTTP + WebSocket 载体 | **1421 网关**（Axum），默认绑 127.0.0.1 |
| 宿主中介的服务契约 | **MCP over HTTP**，已挂在网关上 |
| 鉴权 | 网关**默认拒绝**（v0.32.0 改的），回环免令牌、其余要凭据 |
| 路由不漏登记 | `router_coverage_tests` 扫 `proxy.rs` 的 `.route(...)` |

也就是说：真要开插件生态，OMNIX 缺的不是管道，是**契约和生命周期**。

## 三、如果要做：三个阶段

### 阶段 1 · 契约（不写任何加载器）

先把「插件能调什么」定死成一份 MCP 工具清单，并**明确哪些是私有的**。
现在 OMNIX 的 MCP 工具是内部用的，没有公私之分——开放之前必须先分。

判据：一份文档 + 一条守卫测试（公开工具清单变动必须是显式提交，
和 `KNOWN_ORPHANS` 同一种棘轮）。

### 阶段 2 · 清单与隔离

- 插件 = 一个目录 + 一份 manifest（名字、版本、需要哪些公开工具、UI 插槽）
- **不给文件系统、不给子进程、不给原生 API**——一律走网关
- 权限按 manifest 声明，装的时候让用户看见（照 `capabilities/default.json` 的思路）

### 阶段 3 · 生命周期

照搬 DSH 的 generation：切换工作区/profile 整代重来，插件不许跨代持有句柄。
**这一条现在就可以先用在自己身上**——OMNIX 的 `runtimeSessionByConversationRef`
之类的跨代缓存，正是这轮修「状态撒谎」时反复碰到的东西。

## 四、UI 插槽

DSH 把桌面自己也做成插槽贡献。OMNIX 现在是 31 个硬编码 Tab，要做的话：

1. 先把 Tab 注册表化（一份清单，而不是 `App.tsx` 里的 switch）
2. 插槽只开**两处**：新增 Tab、侧栏条目。不要一上来就开满
3. 插件 UI 跑在 sandbox iframe 里（HTML 预览已经在用 `sandbox=""`，有现成范式）

## 五、为什么建议缓做

**这个项目的历史问题恰恰是「接了没用的东西太多」。** 这轮清理的账：

- 未用 API 包装 21 → 0
- 孤儿命令 17 → 5
- 注册命令 454 → 402
- 只写不读的表：一轮挖出六处

插件系统会把这个问题**放大一个量级**：每个插件都是一组新的接缝，而接缝正是这个
项目最高产的 bug 来源。DSH 有 4,800 个插件是因为它有生态；OMNIX 现在没有外部
开发者，做出来的插件系统只有自己用——那就是「为了架构而架构」。

**触发条件**（满足任一再做）：
- 有外部开发者明确要接；
- 或者你自己有 ≥3 个功能，明显该做成可插拔而不是内置。

**现在就可以做的，是阶段 3 的纪律**：不跨代缓存句柄。那一条不需要插件系统，
本身就能让「状态撒谎」这类问题少一批。

## 六、不做

- **不做插件市场 / 远程分发。** 那是运营，不是工程。
- **不做进程级插件**（每个插件一个子进程）。OMNIX 已经在管 8 个 agent CLI 的
  进程生命周期，再加一批是找事。走网关的 HTTP 契约就够。
