# 深度研究（Deep Research）方案

> 状态：**已设计，未实施**。2026-08-20 定稿。
> 前置：无。现有的搜索、`fetch_url`、RAG 分块都已就位，缺的只是「迭代」这一环。

## 一、现状盘点（实测）

OMNIX 已经有的：

| 件 | 位置 |
|---|---|
| 5 家搜索供应商 | `commands/search.rs`（brave / duckduckgo / exa / google / tavily） |
| 抓网页 + SSRF 笼 | `fetch_url`，公网校验 + 重定向后复查 + DNS 解析后复查 |
| 文档分块 + 混合检索 | `knowledge.rs`（BM25 + 向量 + RRF） |
| 对外供能 | MCP over HTTP，挂在 1421 网关上 |

**缺的是迭代**：现在是「搜一次 → 拿结果 → 结束」，没有「读完之后发现还差什么 →
再搜」这一环。

## 三、设计：不新造编排层

**明确不做的：把 LangGraph 那套 agent 编排搬过来。** OMNIX 本身就是编排器，
再叠一层是加机器；而且那样等于把「研究」做成一个跟对话平行的封闭系统，
用户的工作区、记忆、技能都进不去。

**做法：一个技能 + 三个 MCP 工具。** 迭代循环让 agent 自己跑（它本来就擅长这个），
OMNIX 负责提供工具、存证、和一份「怎么做研究」的技能说明。

### 三个核心机制

**① 迭代循环**

```
提问 → 搜 → 读 → 提炼「还没答上的子问题」 → 再搜 → …
```

停止条件用**「新一轮没有产生新子问题」或轮数上限**，不要用固定轮数——固定轮数
在简单问题上浪费，在复杂问题上不够。

**② 引文强制（这条是分水岭）**

每个结论必须挂来源 URL + 原文片段。**这是 deep research 和「搜一下然后总结」的
唯一实质区别**——没有引文的多轮搜索只是多花了几倍 token 的普通搜索。

落地：`research_note(claim, source_url, snippet)` 工具，把每条结论连同证据落库。
最后成文时从库里取，不是让模型凭记忆复述。

**③ 来源分级**

local-deep-research 用期刊评分。OMNIX 不做学术，但**已经有等价机制**：记忆库的
「分级可信度」（`verified` / `confidence` / `repeated_count`）。同一个模式，
给来源打等级即可——官方文档 > 一手仓库 > 技术博客 > 论坛回答 > 内容农场。

### 三个 MCP 工具

| 工具 | 作用 |
|---|---|
| `research_start(question)` | 开一次研究，落一条记录，返回 research_id |
| `research_note(research_id, claim, source_url, snippet, tier)` | 记一条带证据的结论 |
| `research_report(research_id)` | 从库里取全部笔记，出带引文的报告 |

搜索和抓取**复用现成的** `search` / `fetch_url`，不新造。

### 技能

一份 `deep-research` 技能，写清楚：什么时候该用、循环怎么走、什么时候停、
每条结论必须带证据。**照 stablyai/orca 的「发现桩」写法**——技能里只写「怎么用」，
工具清单由 MCP 现取，免得技能文件和实现漂开。

## 四、数据

两张表：

```sql
research_runs(id, question, status, created_at, finished_at)
research_notes(id, research_id, claim, source_url, snippet, tier, created_at)
```

**注意**：加表就要同时想好谁读它——本项目最高产的 bug 模式就是「写了但没人读」。
这两张表的读取端是 `research_report`，必须一起做，不能先建表后补。

## 五、验收判据

- **引文覆盖率**：报告里每个结论都能点回一个 URL + 片段。做一条测试：给定一组
  假搜索结果，产出的报告里不许出现没有来源的断言。
- **迭代真的发生了**：一个需要两跳才能答的问题（A 里提到 B，答案在 B），
  单轮搜索答不出来，迭代能答出来。这是**唯一能证明迭代有价值**的判据。
- **停得下来**：一个无解的问题不会无限循环。

## 六、不做

- **不做独立的研究 Tab。** 研究是对话的一种，走现有会话，产出物落知识库。
- **不做自己的搜索聚合。** 5 家够用，缺的是循环不是来源。
- **不做学术数据库接入**（arXiv/PubMed 那套）。除非你真的要做学术检索——
  那是另一个产品。

## 七、工作量估计

阶段 1（两张表 + 三个 MCP 工具 + 技能）是主体；阶段 2（来源分级）复用记忆库的
分级机制；阶段 3（报告成文）最简单。**建议一次做完阶段 1 再评估**——如果 agent
拿着这三个工具已经能做出带引文的多跳研究，后面两阶段可能都不必做。
